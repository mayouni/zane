Gotchas · the forms family

A form is a conversation in which the system asks questions of a user, a person or an agent.

A form is the part of an interface through which the system asks a user for the information it needs. The rules of forms keep the question in view while a person answers it, and they prevent the system from blaming the user for its own confusion. The two violations on this page break the conversation from both sides: an error message that blames the user for the system's confusion, and a question that vanishes from sight as soon as the person starts to answer it.

"Invalid input!": an error message that blames the user and does not say how to fix the entry Rule 40 · Non-Accusatory Pathfinding

Type an incomplete email address, for example aminata@, in each field, then leave the field with Tab or by clicking elsewhere.

The offense

This message blames the user, explains nothing and shouts in red.

Under the law

This message states what the system requires, with a verb that tells the user how to fix the entry. The message fades as soon as the user starts to correct the entry.

Why it is law: the error is the system's failure to understand the entry, and a message that says so calmly keeps the person's dignity and momentum. Every error message must contain a verb that tells the user how to move forward.

The Vanishing Label: a field whose question disappears when the person starts to answer it Rule 28 · Forms as Conversations

Start typing in both fields. Then suppose that the phone rang and you came back two minutes later, and check whether each field still shows what it asks.

The offense

The placeholder serves as the label. When the person types, the placeholder vanishes, and the question vanishes with it.

Under the law

The label sits above the field and is always visible, so the conversation keeps its question in view.

Why it is law: a form is the system asking a user questions, and a form that hides its question during the answer turns the conversation into an interrogation.
