Gotchas · the stillness family

Stillness means that the frame of an interface holds still and reports a result only when it is true.

Stillness is the property of an interface whose content does not move under a person's eyes and whose feedback does not announce a result before the system knows it. Stillness lets a person keep their place while reading and trust what the interface reports, so it is a functional requirement and not an aesthetic choice. The two violations on this page attack stillness from both ends of time: content that shoves the text being read when the content arrives, and feedback that announces success before the system knows the result. Trigger both violations, then do the same things in the lawful twins, which keep the frame still and honest.

The Shove: an error message that pushes the text a person is reading Rule 38 · Zero Displacement

In this demo a person is reading a paragraph when an error message appears. Press each Submit button and watch whether the paragraph moves.

The offense

This is the paragraph a person is reading. The error message appears above it and shoves it down.

Under the law
We need an amount before saving — add one above.

This is the same paragraph. The space for the error message is reserved, so when the message appears, nothing the person is reading moves.

Why it is law: a layout shift breaks the ocular groove: the eye loses its place, and the mind spends effort to find it again. Reserved space keeps the frame still. The declaration checker names this violation LAYOUT_DISPLACEMENT.

The Lying Success: a save message that reports success before the system confirms it Rule 18 · The Speed of Thought

Press both Save buttons. The violation reports success at once, and four seconds later it reports what really happened.

The offense

This message reports success before the system knows the result. The calm it gives is false, and it costs the person more when the truth arrives.

Under the law

The interface acknowledges the press within 100ms and says saving, which is not saved. It announces success only when success is true.

Why it is law: an interface must not show "Success" until the system confirms the execution. A fake progress bar is a lie, and trust is the only currency a business tool has.
