Gotchas · the state family

The state of an interface is what the system knows at a given moment, and a user, a person or an agent, must be able to see it and undo changes to it.

State is what the system knows at a given moment, such as which filter is active, and the rules of state make every important part of it visible to the user. The rules ensure that a user never draws a conclusion from a state the user cannot see, and that a user can undo what the user did. The two violations on this page break each promise: a filter that silently changes what the table shows, and a deletion that questions the user twice instead of trusting the user once.

The Invisible Filter: a filter that hides rows without showing that it is active Rule 82 · Visible State

In this demo a manager asks why revenue is down. Revenue is not down: a filter that someone left on hides half of the rows.

The offense
Sales — August
Total

The table looks complete.

Under the law
Sales — August filter: cash only ✕
Total

Click the chip to clear the filter. The state is always visible, and the user can always dismiss it.

Why it is law: a user who draws conclusions from a state the user cannot see has been harmed by the interface. The checker names this violation INVISIBLE_STATE, and the same article requires every norm to carry a message that a person can read.

"Are you sure?": a deletion that asks for confirmation twice instead of offering undo Rule 79 · The Undo Covenant

Press Delete in both panes. The violation questions the user before it trusts the user. The lawful twin trusts the user first and keeps the deletion reversible for ten seconds.

The offense
Invoice #204 — 45,000 XOF

A real browser dialog interrupts the user twice.

Under the law
Invoice #204 — 45,000 XOF

Why it is law: a confirmation dialog always interrupts the user and never trusts the user, while undo trusts the user first and never interrupts. Under the law, a deletion happens at once, visibly and reversibly, and the person keeps the dignity of a ten-second window to undo it. A related diagnostic of the checker, MISSING_UNDO, refuses flows that cannot state the way back.
