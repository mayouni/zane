Language · what the verifier refuses

A refusal names the line, the rule and the right it rests on.

The verifier reads a declaration and either says clean or says no, and a no always carries its reasons. There are 37 diagnostics. This page shows one real refusal, its lawful twin, the envelope any tool can read, and what the diagnostics cannot decide.

Try it on a declaration of your own →

The verifier is one Node file with no dependencies.

One refusal, read line by line

A three-step account opening where the person can undo a step and cancel the step, but there is no way to leave the whole flow.

// A three-step wizard. The person can undo and cancel, but not leave.
DEFINE WIZARD account_opening (
  SATISFIES [UNDERSTAND, CONFIRM, ACT],
  ALWAYS_REACHABLE [UNDO, CANCEL],
  STEPS [identity, funding, review],
  ACTOR applicant
)
$ node tools/zui/cli.js check account_opening.zui
account_opening.zui:2  error  TRAPPED_FLOW  account_opening
    A multi-step flow has no reachable EXIT.
    Rule 51 · The Cognitive Tunnel · Rule 53 · Interaction Lockdown · Article II · the right to leave

1 error(s), 0 warning(s) across 1 file(s) at level 2
  • The line and the subject (account_opening.zui:2, account_opening) say where, so an editor can jump to it.
  • The code (TRAPPED_FLOW) is stable forever: a retired code is never reused, so a rule you wrote against it keeps its meaning.
  • The sentence says what is wrong in terms of the declaration, not of any screen.
  • The citation says why it is wrong: two rules of the law, the article they serve and the right of the person that is at stake. A refusal that cannot say why is not issued.

Exit code 1 is all a CI gate needs. The same declaration with a way out is clean:

// The same wizard with a way out.
DEFINE WIZARD account_opening (
  SATISFIES [UNDERSTAND, CONFIRM, ACT],
  ALWAYS_REACHABLE [UNDO, CANCEL, EXIT],
  STEPS [identity, funding, review],
  ACTOR applicant
)
$ node tools/zui/cli.js check account_opening_exit.zui
clean — 1 file(s), 0 violations at level 2 against Zui v3.13

That pair is a twin: one change, one verdict flips. The suite holds 22 of them, so that the law is tested against what it must allow as well as what it must refuse. The terminal output above is re-run by the site's own check, so it cannot drift from the verifier.

The same refusal, for a machine

Every court in the family speaks one envelope when it refuses, so one CI step, one editor plugin or one dashboard can read all of them. With --json the refusal above is this object, which is the contract's six fields plus the level and the subject the Zui court adds:

$ node tools/zui/cli.js check account_opening.zui --json
{
  "code": "TRAPPED_FLOW",
  "severity": "error",
  "message": "A multi-step flow has no reachable EXIT.",
  "span": { "file": "account_opening.zui", "line": 2 },
  "cites": ["rule:51", "rule:53", "article:intent", "right:leave"],
  "language": "zui",
  "level": 2,
  "subject": "account_opening"
}

The shape is a JSON schema in doc/diagnostic-contract.schema.json; a court that emits it validates against that file. Note the cites: the human text above names the article as a title, the envelope names it by its identifier.

What it can decide, by what it needs to look at

A diagnostic belongs to a level, which is what the verifier must be given before it can decide. Below level 3 the declaration alone is enough. Above it, the verifier needs facts a declaration does not hold, and without them it says nothing, never clean.

LevelIt needsDiagnosticsFixtures
1 · Formnothing but the file1012
2 · Local meaningnothing but the file2256
3 · Across the surfacea symbol table you supply: entities, actors, state45
4 · Painteda rendered surface10

The fixtures counts are the files in the suite that exercise each level, so level 4 says what it is: a diagnostic is defined and nothing in the suite can yet exercise it, because a rendered surface is not a file. The reference verifier stops at level 2 unless given a table.

The declaration cannot say whether a page looks right, or whether a person understood it. Those are the questions the audit measures after painting and that only a person can answer; see the four steps.

What a refusal does not always cite

Of the 37 diagnostics, 17 cite at least one rule, 8 cite an article but no rule, and 12 cite nothing. The twelve are about the form of the file: a misspelling, a duplicate, a name or value that is not in a closed list. They say the file is not a declaration yet, not that a person is harmed. The eight that cite only an article are places where the law states a principle and has no rule narrow enough to point at.

That is an incomplete grounding, stated as a number rather than hidden. A diagnostic that cites a rule can be traced to its reasons; one that does not can only be trusted as far as the grammar.
