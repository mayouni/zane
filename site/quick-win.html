Try · for anyone who wants to see what an afternoon buys

A quick win is one real run of Zane on a real site, done in under an hour.

A quick win is one short run of Zane on a real site, and it shows where that site stands against the law. It lets a team see what one afternoon of work tells it about a site. The subject of this run is Zing's own site: Zing is a framework in the same family, and this project reads its site and does not own it. The whole run, from the first declaration to the last audit, took forty-seven minutes on 5 November 2026, including the time to mend a tool. The run found one thing, and that thing is not a defect.

1 · The three surfaces of the Zing site, declared in Zane

The run declares three surfaces of Zing's site: the main menu, the style select and the landing page. They are written in the language by hand, from the markup, in examples/quick-win/zing-landing.zane. The file's header says that it is Zane's description of pages that Zane does not own. The part of the file that matters is this declaration:

DEFINE INTERACTION style_select (
  SATISFIES [SELECT],
  ALWAYS_REACHABLE [UNDO, CANCEL],
  ROLE navigate,
  ACTOR reader
)

2 · The verifier's verdict on the declarations

$ node tools/zane/cli.js check examples/quick-win/zing-landing.zane
clean — 1 file(s), 0 violations at level 2 against Zane v3.14

The verifier finds the declarations clean. A style switch changes how the page looks and changes nothing that is true, so it is a selection with a navigating role, which is how Zing built it.

3 · The UI audit of the ten pages of the Zing site

Zing's site was served read only beside the audit with serve-beside.js. The audit ran on its front page and on its nine pages under site/, in the default mode and in Zing's own default style. It reported one finding: the page at site/index.html has no trail and no bar that marks it. That page is a redirect to the front page, is marked not to be indexed, and holds one sentence. No reader stays on it, so the finding is the audit measuring a page that is not a real page. Every page that a reader reads was clean.

A tool was mended during the run, and the repair is part of the result. The first version of the serving script put the audit's own files under /site/, which shadowed Zing's own site/ folder. The script now serves the audit at /__zane/ui-audit.html, a path that no site uses, and the web case's page links this version.

4 · What the quick win shows, and what it does not show

  • The surface was already lawful under what these checks can see. A clean result is still a result: an hour shows a team where it stands, and this site stands well. Zing's own page says that it obeys the law it advertises, which is the likely reason.
  • For comparison, the web case found four real findings on the Softanza site in the same kind of run.
  • Zing's other style was not run. The audit's style switch drives this site's styles, and Zing keeps its own choice under its own name, so only Zing's default style was measured.
  • No person has looked at these pages for this run. The audit measures size, contrast and the path, and it does not judge whether a page is good.
