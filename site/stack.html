Use · for people who choose the stack

This overview of the stack section describes four ways to use Zane inside your own stack, and all four work because a declaration names no stack.

This overview starts from one fact: a declaration states what a user, a person or an agent, is doing and names no stack, so any stack can use it: a team can check it in CI, hand it to a generator, carry it inside Softanza, or implement it again in another language that proves it agrees. This independence ensures that a declaration outlives the tools an interface is built with. The four pages in the list beside this one describe each way.

What the four ways in your stack have in common

All four ways share one law stored as data, one refusal contract and one suite of 77 fixtures, pinned as 12 files by hash. There is no library to adopt: agreement is proved by running the fixtures, never by sharing code. Conformance says how agreement is proved and what a pass does not prove.
