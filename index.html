Zayn, the compilable language for user interfaces

Declare what a user is doing. The law refuses the rest.

A declaration in Zayn names the action, and the verifier checks it against 123 rules before a screen exists; its answer is the rule the declaration breaks, by name and number.

The declaration holds no widget, no layout and no framework, and both reports are the verifier's own output.

What a user does, where, and what the law covers

A declaration is built from 22 verbs, grouped by what a user is doing. The grid crosses those activities with the 10 channels an interface can use, a screen being one, and puts in each cell the rules written for it.

Drawn from the law's own data, and drawn again by the site on every build. The grid, cell by cell ↗

A user is a person or an agent

One declaration serves a clerk at a screen, a caller on a phone line and an agent that a program drives. Each can cancel before the payment and undo it after, and the law holds that promise on every channel.

The three declarations differ by two lines, and one command passes all three. Each sketch shows one way its channel can carry the promise; the renderer belongs to the project that ships it.

The law also knows what a channel cannot carry. A flow that promises to zoom on a voice line is refused, and the report names the promise:

DEFINE VIBE phone_line (
  SURFACE_AS voice,
  MOTION none
)
DEFINE INTENT_FLOW check_balance (
  SATISFIES [UNDERSTAND, ZOOM],
  ALWAYS_REACHABLE [CANCEL, EXIT],
  ACTOR caller
)

In words: a caller checks a balance on a voice line, and the flow promises to zoom.

$ zayn check check_balance.zayn
check_balance.zayn:5  error  VERB_NOT_CARRIED  ZOOM in check_balance on voice
    A declaration satisfies, or promises to keep reachable, an intent the declared medium cannot carry at all.
    Rule 82 · Perceivable State · Article II

1 error(s), 0 warning(s) across 1 file(s) at level 2

In words: the verifier read line 5, marked in the declaration. A voice line cannot zoom (Rule 82), and the report names that one promise and nothing else.

Three ways in, by what you do

Each craft meets the law at its own moment, through the same command.

You design interfaces

You write what a user comes to do, in a closed vocabulary of 22 verbs, and the law answers before a wireframe exists.

  • Check a declaration in the browser
  • Commit each violation beside its lawful twin
  • Measure a live page against the law

You write software

The verifier is one file with nothing to install beside it. Any language calls it as a command, and a build fails when a declaration is refused.

  • Put the law into a build
  • Port it, and prove that the port agrees

You build with AI

A generator declares its intent before it draws, and the law tells it which rule it broke. An agent that uses an interface keeps the rights a person has.

  • Hold a generator to the law
  • Declare a surface an agent uses
  • The rules that govern an agent

A generator declares before it draws

A model repeats the habits of the interfaces it learned from, at machine speed and under any instruction. Zayn gives it a declaration to write first, a grammar that fixes its shape, and a verifier that answers by rule.

The grammar narrows what a generator can write; the verifier judges what it means.

Why a law, and why now

Interfaces built with AI assistants repeat the same defects after explicit instruction. The author of Zayn corrected 480 of them across 26 projects, and 170 of those corrections name an earlier one: the same defect, made again after it was corrected.
