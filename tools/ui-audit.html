The tool · Rules 105, 107, 108, 114–116, measured not guessed

The UI audit measures what a browser paints on any page you can serve beside it.

The UI audit is a tool that opens each page of an application UI and measures what the browser paints, so that the law is checked on the real page. It lets a team settle by arithmetic what the eye argues about: the computed size of every text node, its true contrast against the background actually painted behind it, whether the page shows the whole path it sits on, and whether any block scrolls sideways while the page still has room. The audit works on any UI that you can serve from the same origin: this site, your own project or a generated prototype. Nothing leaves your browser.

The rules that the audit enforces

Rule 105 · The Legibility Floor
Main reading text is at least 1rem, and it is never lighter than 4.5:1 against its background. A ratio of 3:1 is allowed only for genuinely large text, which is ≥24px, or ≥18.66px when bold. A color that carries meaning must also carry contrast.
Rule 107 · Hierarchy Is Not Miniaturization
Three sizes are enough: a hero size, a title size and one reading size. The audit flags anything below the floor, whatever its role: captions, labels, badges, footers and SVG text, whose rendered size is computed from the viewBox scale.
Rule 108 · The Trail Is Always Shown
Every page must carry a breadcrumb that is marked as one (nav[aria-label="Breadcrumb"]) and whose first step returns to the root. Every step must be reachable except the one the reader is standing on. The site root is the only page that is exempt, and the audit reports the exemption instead of staying silent.
Rule 114 · Room Before Scrollbars
The audit flags a block that scrolls sideways whenever the block would have fitted if the layout had given it the page's spare width. Scrolling is lawful only when the page itself has run out of width. The audit measures this at 1280px, which is the width at which it renders each page.
Rule 115 · The Path Shows Every Depth
A path names every level of the branch it sits on, both the levels above and the levels below, so that the whole branch is visible from any page in it. The audit compares the paths of every page that names another page: the paths must read the same, and only the highlight may move.
Rule 116 · The Menu Tells the Truth About the Tree
Every main-menu entry must be a top-level page, or a section that leads to its landing page, and it must use the name that the page's own path uses. The audit reads each page's path. A page that the path puts under a parent may not stand beside that parent as an equal, a page that the menu names differently from its path is one page with two names, and a landing page called by its section's name repeats its parent.

Modern and Retro have different palettes, so a page can be lawful in one vibe and unlawful in the other. The audit reports the vibe that the site is currently in, so run it once in each vibe (press F2, or use the Style picker).

The floor is 16px (Rule 105), and this site reads at 18px. When Strict is unchecked, the audit reports only text that breaks the floor. When Strict is checked, the audit also lists text at 16–17px, which is lawful but smaller than the reading size and is worth knowing about before it spreads.

Ready — press Run the audit.

The report can be pasted into a file, an issue or an AI, and it carries the vibe, the page count and every finding as a table.

The audit works only when the repository is served over HTTP (python -m http.server at the root, or any static server), because the audit reads pages through same-origin frames and the file:// protocol forbids them.
