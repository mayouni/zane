The tool · Rules 105, 107, 108, 114–116, measured not guessed

UI audit

Point it at any application UI you can serve same-origin — this site, your project, a generated prototype. It opens each page and measures what the eye argues about and arithmetic does not: the computed size of every text node, its true contrast against the background actually painted behind it, whether the page shows the whole path it sits on, and whether any block scrolls sideways while the page still has room. Nothing leaves your browser.

What it enforces

Rule 105 · The Legibility Floor

Main reading text at least 1rem, never lighter than 4.5:1 against its background (3:1 is allowed only for genuinely large text: ≥24px, or ≥18.66px bold). A color that carries meaning must also carry contrast.

read the rule

Rule 107 · Hierarchy Is Not Miniaturization

Three sizes suffice — hero, title, and one reading size. Anything below the floor is flagged, whatever its role: captions, labels, badges, footers, and SVG text (whose rendered size is computed from the viewBox scale).

read the rule

Rule 108 · The Trail Is Always Shown

Every page must carry a breadcrumb — marked as one (nav[aria-label="Breadcrumb"]) — whose first step returns to the root, with every step reachable but the one you are standing on. The site root is the only page exempt, and the audit says so rather than staying silent.

read the rule

Rule 114 · Room Before Scrollbars

A block that scrolls sideways is flagged whenever it would have fitted had the layout given it the page's spare width. Scrolling is lawful only when the page itself has run out — measured at 1280px, the width the audit renders at.

read the rule

Rule 115 · The Path Shows Every Depth

A path names every level of the branch it sits on — the ones above and the ones below — so the whole picture is visible from anywhere in it. The audit compares the paths of every page that names another: they must read the same, with only the highlight moving.

read the rule

Rule 116 · The Menu Tells the Truth About the Tree

Every main-menu entry must be a top-level page, and must call that page what the page's own path calls it. The audit reads each page's path: a page the path puts under a parent may not stand beside that parent as an equal, and a page the menu names differently from its path is one page with two names.

read the rule

Both vibes

Modern and Retro have different palettes, so a page can be lawful in one and unlawful in the other. Run it twice — the audit reports whichever vibe the site is currently in (press F2, or use the Style picker).

Pages to audit

One path per line, relative to the site root. Add your own project's screens the same way.

The floor is 16px (Rule 105) and this site reads at 18px. Left unchecked, the audit reports only text that breaks the floor; checked, it also lists the 16–17px text — lawful, but smaller than the reading size, which is worth knowing before it spreads.

Not run yet — press Run the audit.

Paste it into a file, an issue, or an AI — it carries the vibe, the page count, and every finding as a table.

Serve the repository over HTTP for this to work (python -m http.server at the root, or any static server); the audit reads pages through same-origin frames, which the file:// protocol forbids. The static half of these rules is also enforceable before rendering: Zing's zing check, the first conforming linter, flags sub-floor font sizes in a project's declarations, citing Rule 107.
